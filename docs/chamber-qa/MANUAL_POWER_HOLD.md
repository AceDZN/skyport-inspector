# Optional manual freight brake

A later authored three-stop manual freight route needs actual power loss to brake in place, rather than pretending an existing return-to-base actuator already does so. `DeviceSpec.holdOnPowerLoss` now opts the manual lift branch into holding its real current pose/selected stop when its circuit loses power. Restored power resumes that target through the ordinary bounded motor steps. Default manual lifts still return to BASE on loss; cyclic carriers retain their previous phase-freezing behaviour. No RoomID/speed/use/history/goal gate is added.

`manual-power-hold-before.txt` preserved1/3: the unconfigured default passed while the requested held-pose and brake-cue contracts correctly failed. After the optional branch was implemented, `manual-power-hold-first.txt` passed3/3. Two native authored-input fixture cases use real E/WASD/aim to board, ride, remove the actual pressure cube, wait safely on the deck with loose cargo, replace pressure and resume; the opted-in case repeats upward and downward. Player/cargo/deck are never positioned or velocity-written by the driver. Native dock flags stayfalse while braked between stops; two actual brake events occur,0resets and no campaign completion.

The third isolated machine contract checks one brake per power-loss episode, no invented arrival and one restore motor event. `manual-power-hold-validation/` then sequentially compiled source/test and passed32 affected machinery/seam/clock/default/native cases with exact pre/post source match. It does not substitute for later38 ordinary-input audiovisual acceptance. All prior devices omit the flag and retain their existing behaviour.
