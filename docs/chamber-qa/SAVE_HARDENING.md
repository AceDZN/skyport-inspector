## Storage contract

The core key stays `rift-runner-rapier-campaign-v1`; the rejected prototype's default remains isolated at `rift-runner-campaign-v2`. JSON version stays2. Existing CJ/Bh saves without `generation` belong to the legacy generation. Actual imported1/2 measurements stay null; untagged historical observations stay unattributed, and real base/contrast evidence is retained separately. No completion is inferred from a backup filename, missing record or a requested unlock.

Ordinary entry/observation reads the latest main and protected `<key>-journal`, merges same-generation completed records/frontier and variant evidence, then writes/verifies the journal **before** updating main. A loaded old client can blindly overwrite main, but the journal remains recoverable on the next new-code load. Within the same generation, counts/frontier are monotonic and newer observed per-variant evidence is retained. Constructor recovery is read-only: a malformed main is not replaced merely by opening the page.

Explicit New Game first reads current authority and verifies a real `<key>-backup` when there is progress. If that backup cannot be retained, reset is refused. New Game and explicit restore each create a new opaque generation. The journal's generation is authoritative over old-generation main writes. A stale instance adopts current progress but cannot record its old run result until a new `enter`; even an old level1 completion is rejected. A valid empty reset prevents automatic legacy1/2 remigration. Restore copies only real backed-up records and creates a new generation; it does not merge separate campaigns together.

Unreadable/partial main, journal and overwritten backup values require exact verified quarantine copies under `<affected-key>-unreadable-<hash>[-collision-suffix]` before replacement. If preservation/read access fails, unknown stored data is not replaced. A valid journal or compatible backup can recover actual records; a partially decoded main can recover missing same-generation records from a valid backup. Storage failures leave actual session play possible and expose warnings. If the primary write alone fails after a verified journal write, the journal remains durable authority.

## Verification and limits

All29 tests in `npx tsx --test tests/progression.test.ts` pass. They cover stale two-instance entry/observations; original-client direct main overwrite followed by reload; reset generation authority and stale level1 results; verified backup/restore; exact corruption/empty/partial quarantine; main/journal/backup write failures; storage read recovery; genuine exported CJ legacy1/2+earned3 base/contrast and fresh1–5 data; default namespace isolation. No browser, parent storage, unlock injection or native rendering is involved. Full `npx tsc --noEmit` passes. The assigned frozen-build browser acceptance is recorded in `SAVE_ACCEPTANCE.md`; it uses an actual fresh C1 win and a separately imported genuine earned CJ1–5 export. It does not reconstruct the earlier parent loss or exercise a stale physical completion after the storage event has already discarded that run.

An already-loaded pre-hardening client's **explicit** New Game has no generation marker and cannot be distinguished from its blind stale overwrite. The new journal therefore retains earned data in either case; intentional resets must use the new code. This protocol does not claim a multi-key database transaction or compare-and-swap: localStorage provides neither. It protects the tested ordered stale-write/reload/failure paths; a simultaneous cross-process interleaving still requires separate locking if that stronger guarantee is needed. No inference is made that any of these paths caused the parent's earlier loss, and the patch cannot reconstruct already-lost records without an actual surviving journal, backup or earned export.
